### News ticker-এর acceptance criteria

- Dashboard-এর উপরের অংশে horizontal scrolling headline ticker।
- একাধিক অনুমোদিত source নির্বাচন করার ব্যবস্থা।
- প্রতিটি headline-এর সঙ্গে publisher/source name ও original article URL।
- Headline-এ চাপ দিলে original article browser বা in-app browser-এ খুলবে।
- Loading, no news, timeout ও network error-এর অবস্থা থাকবে।
- Duplicate headline বাদ দেওয়া হবে।
- Last successful fetch-এর data সীমিত সময় cache করা যাবে।
- নির্দিষ্ট interval-এ refresh হবে; প্রতিটি scroll movement-এ নতুন request যাবে না।
- Source unavailable হলে অ্যাপের বাকি অংশ চলবে।
- কোনো paywall, login restriction বা anti-bot ব্যবস্থা bypass করা হবে না।
- অনুমতি ছাড়া পূর্ণ article text বা ছবি কপি করে DhakaLife-এ দেখানো হবে না।

প্রস্তাবিত fallback: যদি অনুমোদিত feed/API না পাওয়া যায়, প্রথম সংস্করণে source-এর নাম ও official website-এ যাওয়ার link দেখান। পরে অনুমোদিত feed বা licensed news provider যুক্ত করুন। ওয়েবসাইটের homepage থেকে সরাসরি scraping-কে production solution ধরে নেবেন না।

### Radio-এর গুরুত্বপূর্ণ requirements

- প্রথমে ৩–৫টি যাচাইকৃত, বৈধভাবে ব্যবহারযোগ্য Bangla radio station দিয়ে শুরু।
- Station name, logo (যদি ব্যবহারের অনুমতি থাকে), genre এবং live status।
- Play/Pause/Stop ও station change।
- Screen off বা app background-এ গেলেও playback চলবে।
- Android media notification ও lock-screen controls।
- Headphone unplug করলে playback pause করার উপযুক্ত আচরণ।
- Incoming call বা অন্য audio interruption হলে playback সঠিকভাবে handle করা।
- Network disconnect হলে error এবং retry।
- ব্যবহারকারী Stop করলে background playback service বন্ধ হবে।
- Stream URL বৈধ HTTPS বা provider-supported streaming URL হলে অগ্রাধিকার।

Radio stream-এর ব্যাপারে সতর্কতা: “Free to listen” মানেই অন্য app-এ stream পুনঃপ্রচার বা embedded player হিসেবে ব্যবহার করার অনুমতি আছে—এমন নয়। প্রতিটি station-এর official stream URL, ব্যবহার-শর্ত ও পুনঃপ্রচার-সংক্রান্ত অনুমতি যাচাই করতে হবে। কোনো অনুমোদিত stream URL না পাওয়া পর্যন্ত placeholder station দিয়ে UI তৈরি করা যেতে পারে, কিন্তু সেটিকে real radio হিসেবে ঘোষণা করা যাবে না।

## ৪. Android radio-এর জন্য বিশেষ technical checks

Radio background playback শুধু screen বন্ধ হওয়ার পর timer চালিয়ে রাখার বিষয় নয়। Android media playback service সঠিকভাবে configure করতে হবে।

Antigravity-কে বলবেন:

- `audio_service` ও `just_audio`-এর compatible versions যাচাই করতে।
- Android manifest-এ প্রয়োজনীয় foreground-service ও media-playback declarations যোগ করতে।
- Android version অনুযায়ী notification permission এবং media notification আচরণ পরীক্ষা করতে।
- Audio handler দিয়ে play, pause, stop ও station switching implement করতে।
- Background service চালু থাকলে ব্যবহারকারী যেন notification থেকে playback বন্ধ করতে পারেন।
- Android battery optimization ও manufacturer-specific background restrictions-এর কারণে playback আচরণ বাস্তব device-এ পরীক্ষা করতে।
- Service বা app process বন্ধ হলে কী হবে তা স্পষ্টভাবে নির্ধারণ করতে; ব্যবহারকারী Stop করার পর radio যেন নিজে থেকে আবার চালু না হয়।

Official package documentation: [audio_service](https://pub.dev/packages/audio_service) এবং [just_audio](https://pub.dev/packages/just_audio)।

  5. Gradual activation of remaining Dhaka utility features

## 2. Non-Negotiable Preservation Rules

1. Inspect the actual repository before editing.
2. Do not rewrite the app or replace its architecture.
3. Do not delete working screens, features, routes, assets or databases.
4. Do not remove existing mock features until their replacements pass testing.
5. Preserve the current dashboard design wherever possible.
6. Reuse the current state management, routing, theme and service conventions.
7. Do not upgrade unrelated packages or SDKs unnecessarily.
8. Preserve uncommitted user changes.
9. Do not invent API endpoints, radio stream URLs, credentials or test results.
10. Do not begin all phases in one large implementation.

Inspect and report:
- `pubspec.yaml`
- `lib/main.dart`
- All relevant `lib/` directories and screens
- Existing models, services, networking and state management
- Android manifest and Gradle configuration
- Existing tests and assets
- `.gitignore`, `README.md` and `PROJECT_CONTEXT.md`
- Git branch, status and recent commits
- Mock data and incomplete features

Run and record, where supported:
- `flutter --version`
- `dart --version`
- `flutter doctor -v`
- `flutter pub get`
- `flutter analyze`
- `flutter test`
- `flutter devices`

Identify pre-existing problems separately from new problems.

## 4. Implementation Order

### Phase 0 — Baseline

Document current functionality, existing mock data, architecture, commands and known issues. Create or update `PROJECT_CONTEXT.md`. Establish a safe Git checkpoint without overwriting user work.

### Phase 1 — Live Weather

Integrate Open-Meteo using its documented forecast endpoint:
https://open-meteo.com/en/docs

Initial coordinates:
- Latitude: 23.8103
- Longitude: 90.4125
- Time zone: Asia/Dhaka

Implement a typed model, networking service, timeout, HTTP validation, safe parsing, loading/error/retry UI and automated tests. Use the existing dashboard weather component. Do not request location permission in this phase.

### Phase 2 — Bangla News Ticker

Candidate sources:
- https://epaper.prothomalo.com/Home/
- https://bangla.bdnews24.com/

Investigate official RSS feeds, documented APIs, licensing and source usage terms before implementation.

Requirements:
- Horizontal scrolling headlines in the upper dashboard area
- Source/publisher attribution
- Clickable original article links
- Refresh and sensible caching
- Duplicate filtering
- Timeout, empty and error states
- No duplicate polling for each animation frame
- Preserve the app when a news source is unavailable

Do not assume an e-paper homepage is a permitted news API. Do not bypass paywalls, authentication or anti-bot protections. Do not republish full article text, images or copyrighted content without permission.

If an approved feed or API cannot be verified, implement a source-link fallback and document the blocker. Do not scrape production news pages without permission.

### Phase 3 — Bangla Radio

Investigate:
- `just_audio`
- `audio_service`
- Compatibility with the project's current Flutter/Dart constraints
- Android foreground media playback requirements
- Required manifest declarations and Android version behavior
- Media notification, lock-screen and headset controls

Use only verified, authorized radio stream URLs. Never invent a working stream URL.

Implement:
- Station list and station selection
- Play, pause and stop
- Current station display
- Background playback while the screen is off
- Media notification and lock-screen controls
- Network failure and retry
- Audio interruptions and headphone removal behavior
- Correct service shutdown when the user stops playback

Use clearly labeled placeholder stations if valid stream URLs have not yet been verified. Do not claim that placeholder streams work.

Test on a physical Android device, not only in a widget test or emulator.

### Phase 4 — Map and Nearby Places

Evaluate OpenStreetMap-based mapping and Overpass queries. Respect tile usage policies, attribution, rate limits, caching rules and provider terms. Add location permission only when needed and retain a manual-location fallback.

### Phase 5 — Core Dhaka Features

Prioritize verified emergency information, service discovery, transport-route prototypes and useful Bangla utilities. Clearly label informational data and provide source links. Never invent official contact details.

### Phase 6 — Backend, Storage and Notifications

Only introduce Firebase, Supabase or a custom backend when a demonstrated requirement needs it. Document costs, limitations, data model, access rules and privacy implications. Do not migrate or replace an existing database without explicit approval.

### Phase 7 — Release Readiness

Run regression tests, build the APK, test network failure and background behavior, review privacy/security, verify third-party attribution and document release steps.

## 5. Testing Requirements

For every implemented phase:
- Add deterministic unit tests using mock responses where appropriate.
- Add widget tests for loading, success, empty and error states.
- Run `flutter analyze` and `flutter test`.
- Run `flutter build apk --debug` when supported.
- Verify the feature manually on Android.
- Record exact commands, results and failures.
- Do not report an unexecuted test as passing.

For Radio specifically, verify screen-off playback, notification controls, lock-screen behavior, stream failure, network disconnection, audio interruption and explicit Stop behavior.

For News specifically, verify source attribution, article navigation, unavailable feeds, duplicate headlines and permitted content usage.

## 6. PROJECT_CONTEXT.md Maintenance

After every phase, update the existing root `PROJECT_CONTEXT.md` without destroying valid earlier documentation.

Maintain:
- Current project status and active phase
- Repository structure and architecture
- Actual files changed and their purpose
- Dependencies and API sources
- Data flow and configuration
- Permissions and platform-specific requirements
- API limitations and licensing considerations
- Test/build commands and actual results
- Known issues and unresolved decisions
- Git checkpoint/commit when verified
- Date-stamped changelog
- Exact next task

Separate verified facts, assumptions and planned work.

## 7. Workflow and Approval Gates

For each phase:
1. Inspect.
2. Propose the minimal file changes.
3. Implement only the current phase.
4. Run tests and inspect the diff.
